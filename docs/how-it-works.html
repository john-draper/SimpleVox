How It Works

A four-stage pipeline that transforms your video from raw audio to a seamlessly censored final cut.

The big picture

SimpleVox processes a video file through four distinct stages. Each stage takes the output of the previous one and passes its result forward — together they form an end-to-end profanity filter that runs entirely on your machine.

video.mkv ──▶ [1. Transcribe] ──▶ words.json │ ▼ [2. Find Replacements] ──▶ replacements.json │ ▼ [3. Generate Audio] ──▶ *.wav │ ▼ [4. Splice + Mux] ──▶ video_censored.mkv (censored audio + ORIGINAL video stream, copied losslessly)

When you run python run.py, all four stages execute automatically. But each stage is also a standalone script you can run individually for debugging or experimentation.

Stage 1 — Transcription

transcribe.py uses WhisperX to transcribe the audio track with word-level timestamps. WhisperX is built on OpenAI's Whisper model but adds forced alignment, which dramatically improves the accuracy of per-word start/end times — essential for clean splicing later.

How it works

  • ffmpeg extracts the audio track from the video container
  • The Whisper model runs GPU-accelerated (VAD-batched) transcription
  • A phoneme alignment model refines word boundaries to millisecond precision
  • Results are flattened into a simple JSON list: {"word", "start", "end"}

Run it standalone

$ python transcribe.py "input/video.mkv" -o output/words.json

Key options

  • --model small — Whisper model size (tiny, base, small, medium, large-v3). Bigger = more accurate, slower.
  • --device cuda — Force GPU or CPU. Defaults to auto-detect.
  • --compute-type float16 — Lower precision = faster, less VRAM. Use int8 for CPU.
  • --language en — Language code, or auto to detect.

Stage 2 — Profanity Detection

replacements.py matches each transcribed word against a built-in dictionary of profanity → euphemism mappings. The matching is case-insensitive and ignores surrounding punctuation, so "Damn," matches the key damn.

The dictionary

The REPLACEMENTS dict is a plain Python dictionary — fully editable. It covers common profanity families (ass, shit, fuck, bitch, damn) with hundreds of inflections, plurals, compounds, and hyphenated variants:

# A small sample from replacements.py REPLACEMENTS = { "bitch": "brat", "bitches": "brats", "fuck": "freak", "fucking": "stinking", "shit": "crap", "damn": "dang", # ...hundreds more }

Design choices

Euphemisms are chosen to sound genuinely different from the original — different vowels, different ending consonants. For example, bitch → brat (not "bench", which sounds too similar). Hyphenated forms like half-assed get their own keys because the matcher preserves internal punctuation.

Note: The matcher checks one word at a time, so multi-word phrases aren't supported yet. Adding phrase matching is a planned enhancement.

Stage 3 — Audio Generation

generate_audio.py generates a .wav file for each replacement word using edge-tts — Microsoft's free neural text-to-speech. Every word is spoken by the same natural-sounding voice, creating consistency across the whole video.

Why one voice?

Using a single generic voice keeps the pipeline simple, free, and fast. There's no voice cloning, no per-speaker models, and no API keys — just clean, high-quality neural TTS that runs in seconds.

Run it standalone

$ python generate_audio.py output/movie_replacements.json --output-dir output/generated_audio

Choosing a voice

The default is en-US-GuyNeural, a conversational US male voice. You can switch with --voice:

Voice IDStyle
en-US-GuyNeuralConversational US male (default)
en-US-DavisNeuralWarm US male
en-GB-RyanNeuralBritish male
en-AU-WilliamNeuralAustralian male

Stage 4 — Splice & Mux

splice_audio.py is the most intricate stage. It builds the final censored audio track by stitching together the original audio with the generated replacements, then muxes it with the untouched video stream.

What it does

  1. Sorts replacements by start time
  2. Extracts each "gap" segment (the original audio between replacement words) with ffmpeg
  3. For each replacement:
    • Time-stretches or trims it to exactly match the original word's duration (keeps A/V sync)
    • Loudness-matches it to the original word's volume
    • Applies 20ms fades at boundaries for seamless blending
  4. Concatenates all segments into one censored audio track
  5. Muxes the clean audio with the original video stream (copied losslessly via -c:v copy)

The result

A new video file with identical picture quality and a censored soundtrack. The original video stream is never re-encoded — it's copied bit-for-bit. If your player or container has trouble with a stream copy, set VIDEO_REENCODE=1 to re-encode the video as a fallback.

Run it standalone

$ python splice_audio.py "input/video.mkv" \ --replacements-json output/movie_replacements.json \ --audio-dir output/generated_audio \ --output output/video_censored.mkv
